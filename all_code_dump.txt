# InboxFlow

InboxFlow is a modular, event-driven communication automation platform. This repository contains multiple services including a Lambda-based IMAP sync module, an API, a frontend, and more.

## Table of Contents
- [Project Structure](#project-structure)
- [Automated Local Environment Setup](#automated-local-environment-setup)
- [Building, Packaging, and Deployment](#building-packaging-and-deployment)
- [Running and Testing Services](#running-and-testing-services)
- [Unified Environment Startup](#unified-environment-startup)
- [Production Deployment](#production-deployment)
- [Additional Notes](#additional-notes)

---

## Project Structure

- **inboxflow_dispatcher/**: Contains the Dispatcher Service.
- **inboxflow_imap-sync/**: Contains the IMAP sync service.
- **inboxflow_api/**: Contains the API service.
- **inboxflow_frontend/**: Contains the frontend UI.
- **inboxflow_infrastructure/**: Contains Terraform configurations for infrastructure.
- **inboxflow_docker-compose/**: Contains Docker Compose configuration (e.g., for the Postgres database).
- **Makefile**: Contains targets for building, running, testing services, packaging the Lambda function, and deploying via Terraform.

---

## Automated Local Environment Setup

1. **Environment Configuration**  
   Ensure you have a `.env` file in the project root with your local environment variables.

2. **Starting LocalStack**  
   Run:  
   ```make localstack-up```  
   This command starts LocalStack with the Docker socket mounted so that Lambda functions can run using Docker.

3. **Starting the Database**  
   Instead of manually switching to the docker-compose directory, use:  
   ```make run-db```  
   This target uses Docker Compose (with the configuration in the ```inboxflow_docker-compose``` folder) to start the Postgres container and mount the migration file for automatic initialization.  
   **Note:** The migration file is automatically applied only when the database is created (i.e., when the data volume is empty).

---

## Building, Packaging, and Deployment

- **Packaging the Lambda Function**  
  Run:  
  ```make package-lambda```  
  This packages your IMAP sync Lambda function.

- **Deploying with Terraform**  
  Run:  
  ```make deploy-lambda```  
  This deploys your Lambda and associated infrastructure (using LocalStack endpoints).

- **Building All Services**  
  Run:  
  ```make build-all```  
  This builds Docker images for all services (including database migration if applicable).

---

## Running and Testing Services

- **Running All Services**  
  Run:  
  ```make run-all```  
  This target now includes starting the database (via ```run-db```), the dispatcher, API, frontend, and flows services.

- **Running Tests**  
  Run:  
  ```make test-all```  
  This executes test suites for all services.

---

## Unified Environment Startup

To streamline your workflow and reduce the number of steps, you can now start the entire local environment with just one command. The new setup ensures that LocalStack, the Postgres database (with automatic migration), and all services are started together. Simply run:

```make run-all```

This command will:
- Start the Postgres database container using Docker Compose (via the ```run-db``` target).
- Build and start all services (dispatcher, API, frontend, flows, etc.).
- Ensure that the migration file is mounted and applied automatically on first run.

---

## Production Deployment

For production deployment:
- Create a production environment file (e.g., ```.env.prod```) with real AWS credentials and settings.
- Update Terraform variable files as needed.
- Run:  
  ```make deploy-prod```

---

## Additional Notes

- **Environment Switching:**  
  Use ```make local-env``` for local settings and ```make prod-env``` (if configured) for production settings.

- **Automation:**  
  The Makefile automates environment setup, migration, building, and running services. This can be integrated into your CI/CD pipeline.

- **Resource Exposure:**  
  The frontend is publicly exposed while backend resources remain secured.

from fastapi import FastAPI, HTTPException, Query
import psycopg2
from config import DB_URL

app = FastAPI()

def get_db_connection():
    return psycopg2.connect(DB_URL)

@app.get("/emails")
def get_emails(filter: str = "all", limit: int = 20, offset: int = 0):
    """Retrieve emails with pagination and filtering."""
    conn = get_db_connection()
    cursor = conn.cursor()
    query = "SELECT id, subject, content, status FROM emails"
    
    if filter == "work-related":
        query += " WHERE subject ILIKE '%recruiter%' OR subject ILIKE '%job%'"
    
    query += " ORDER BY received_at DESC LIMIT %s OFFSET %s"
    cursor.execute(query, (limit, offset))
    emails = cursor.fetchall()
    
    conn.close()
    return [{"id": e[0], "subject": e[1], "content": e[2], "status": e[3]} for e in emails]

@app.post("/emails/{id}/decision")
def decide_email(id: str, decision: str, edited_response: str = None):
    """Approve, reject, skip, or manually edit AI-generated response."""
    conn = get_db_connection()
    cursor = conn.cursor()
    
    if decision == "Y":
        cursor.execute("UPDATE emails SET status = 'approved' WHERE id = %s", (id,))
    elif decision == "N":
        cursor.execute("UPDATE emails SET status = 'rejected' WHERE id = %s", (id,))
    elif decision == "S":
        cursor.execute("UPDATE emails SET status = 'skipped' WHERE id = %s", (id,))
    elif decision == "M" and edited_response:
        cursor.execute("UPDATE emails SET status = 'edited', content = %s WHERE id = %s", (edited_response, id))
    else:
        conn.close()
        raise HTTPException(status_code=400, detail="Invalid decision value")

    conn.commit()
    conn.close()
    return {"message": "Decision processed successfully"}

@app.post("/sync-emails")
def sync_emails():
    """Triggers manual email sync from IMAP."""
    return {"message": "Sync started. Fetching unread emails from IMAP."}

-- Create the emails table if it doesn't exist
CREATE TABLE IF NOT EXISTS emails (
    id SERIAL PRIMARY KEY,
    subject TEXT NOT NULL,
    sender TEXT NOT NULL,
    received_at TIMESTAMP DEFAULT NOW(),
    content TEXT,
    status TEXT DEFAULT 'pending'
);

-- Now add the last_synced column if it's not already there
ALTER TABLE emails ADD COLUMN IF NOT EXISTS last_synced TIMESTAMP DEFAULT NOW();

-- Existing migrations for other tables
CREATE TABLE IF NOT EXISTS email_flows (
    id SERIAL PRIMARY KEY,
    name TEXT UNIQUE NOT NULL,
    json_config JSONB NOT NULL
);

CREATE TABLE IF NOT EXISTS email_statuses (
    id SERIAL PRIMARY KEY,
    email_id TEXT UNIQUE NOT NULL,
    flow_id INT REFERENCES email_flows(id),
    status TEXT NOT NULL DEFAULT 'pending'
);

CREATE TABLE IF NOT EXISTS saved_filters (
    id SERIAL PRIMARY KEY,
    user_id TEXT NOT NULL,
    name TEXT NOT NULL UNIQUE,
    json_config JSONB NOT NULL
);

# InboxFlow Docker Compose for Local PostgreSQL

This `docker-compose.yml` file sets up a local PostgreSQL database for InboxFlow.

## Services

- **postgres**: A PostgreSQL container configured with:
  - **User**: user
  - **Password**: pass
  - **Database**: inboxflow

The container exposes **port 5432** for connectivity and uses a persistent volume `postgres-data`.

## Usage

1. **Start the database**:
   ```bash
   docker-compose up -d
   ```

2. **Stop the database**:
   ```bash
   docker-compose down
   ```

3. **Check logs**:
   ```bash
   docker-compose logs postgres
   ```

4. **Access PostgreSQL CLI**:
   ```bash
   docker exec -it inboxflow-postgres psql -U user -d inboxflow
   ```

5. **Delete all data** (if needed):
   ```bash
   docker volume rm inboxflow-docker-compose_postgres-data
   ```

# InboxFlow Architecture

## Overview

InboxFlow is designed as a modular, event-driven communication automation system leveraging AWS serverless and autoscaling technologies.

### Core Components

1. **Dispatcher Service** (Polls inbox, enqueues tasks to SQS)
2. **Worker Service** (Processes tasks, applies AI/NLP, generates responses)
3. **API Service** (Exposes RESTful endpoints for interaction)
4. **Frontend Service** (React-based UI for users)
5. **Infrastructure** (Terraform-managed AWS setup: ECS, Lambda, API Gateway, Aurora Serverless)
6. **CI/CD Pipelines** (Automated builds and deployments)

import json
import os

FLOW_DIR = "flows/"

def load_flow(flow_name):
    """Load a flow by name."""
    flow_path = os.path.join(FLOW_DIR, f"{flow_name}.json")
    if not os.path.exists(flow_path):
        return None
    with open(flow_path, "r") as f:
        return json.load(f)

def save_flow(flow_name, flow_data):
    """Save a flow to JSON."""
    os.makedirs(FLOW_DIR, exist_ok=True)
    flow_path = os.path.join(FLOW_DIR, f"{flow_name}.json")
    with open(flow_path, "w") as f:
        json.dump(flow_data, f, indent=2)
    return True

import asyncio
import aioimaplib
import asyncpg
import logging
import os
import boto3
import json
from email.parser import BytesParser

# Configuration from environment or defaults
EMAIL_SERVER = os.getenv("EMAIL_SERVER", "imap.mail.yahoo.com")
EMAIL_USER = os.getenv("EMAIL_USER", "you@example.com")
EMAIL_PASSWORD = os.getenv("EMAIL_PASSWORD", "REDACTED_APP_PASSWORD")  # app password
DB_URL = os.getenv("DB_URL")
BATCH_SIZE = int(os.getenv("BATCH_SIZE", "1000"))
LAMBDA_FUNCTION_NAME = os.getenv("AWS_LAMBDA_FUNCTION_NAME")

# Configure logging
logger = logging.getLogger()
logger.setLevel(logging.INFO)

async def connect_imap():
    """
    Establish and return an asynchronous IMAP connection using aioimaplib.
    Retries on failure.
    """
    try:
        client = aioimaplib.IMAP4_SSL(EMAIL_SERVER)
        await client.wait_hello_from_server()
        await client.login(EMAIL_USER, EMAIL_PASSWORD)
        await client.select("INBOX")
        logger.info("Connected to IMAP server.")
        return client
    except Exception as e:
        logger.error(f"IMAP connection error: {e}. Retrying in 10 seconds...")
        await asyncio.sleep(10)
        return await connect_imap()

async def fetch_uids(client):
    """
    Fetch all message UIDs from the server.
    """
    resp = await client.uid("SEARCH", "ALL")
    if resp.result != 'OK':
        logger.error("Error fetching UIDs.")
        return []
    # Combine response lines and split into UIDs.
    uids_line = b" ".join(resp.lines).decode()
    uids = uids_line.split()
    return uids

async def bulk_fetch_headers(client, uid_list):
    """
    Fetch email headers in bulk (FROM, SUBJECT, DATE) for the given list of UIDs.
    Here we concurrently pipeline header fetches.
    """
    headers = {}
    async def fetch_header(uid):
        resp = await client.uid("FETCH", uid, "(BODY.PEEK[HEADER.FIELDS (FROM SUBJECT DATE)])")
        if resp.result == 'OK' and resp.lines:
            header = b" ".join(resp.lines).decode(errors="ignore")
            headers[uid] = header
        else:
            logger.error(f"Failed to fetch header for UID {uid}")
    await asyncio.gather(*(fetch_header(uid) for uid in uid_list))
    return headers

async def fetch_full_email(client, uid):
    """
    Fetch the full email (RFC822) for a given UID.
    """
    resp = await client.uid("FETCH", uid, "(RFC822)")
    if resp.result == 'OK' and resp.lines:
        raw_email = b"".join(resp.lines)
        return raw_email
    else:
        logger.error(f"Failed to fetch full email for UID {uid}")
        return None

async def fetch_and_process(client, uid, db_pool):
    """
    For a given UID, fetch the full email, parse it, and store it in the database.
    """
    raw_email = await fetch_full_email(client, uid)
    if raw_email:
        try:
            msg = BytesParser().parsebytes(raw_email)
            subject = msg.get("Subject", "No Subject")
            sender = msg.get("From", "Unknown Sender")
            content = raw_email.decode("utf-8", errors="ignore")
        except Exception as e:
            logger.error(f"Error parsing email {uid}: {e}")
            subject = "Parsing Error"
            sender = "Parsing Error"
            content = raw_email.decode("utf-8", errors="ignore")
        async with db_pool.acquire() as conn:
            try:
                await conn.execute(
                    """
                    INSERT INTO emails (id, subject, sender, content, status)
                    VALUES ($1, $2, $3, $4, $5)
                    ON CONFLICT (id) DO NOTHING
                    """,
                    uid, subject, sender, content, "pending"
                )
                logger.info(f"Email {uid} inserted into DB.")
            except Exception as e:
                logger.error(f"DB insertion error for email {uid}: {e}")

async def process_batch(uid_batch, db_pool):
    """
    Process a batch of UIDs concurrently:
      - Optionally fetch headers for preliminary filtering/display.
      - Concurrently fetch full emails and store them.
    """
    client = await connect_imap()
    if not client:
        logger.error("IMAP client connection failed for batch processing.")
        return

    # Fetch headers concurrently (this can be used for lightweight processing if desired)
    headers = await bulk_fetch_headers(client, uid_batch)
    logger.info(f"Fetched headers for UIDs: {list(headers.keys())}")

    # Concurrently fetch and process each email in the batch
    await asyncio.gather(*(fetch_and_process(client, uid, db_pool) for uid in uid_batch))

    await client.logout()

async def cleanup_deleted_emails(all_server_uids, db_pool):
    """
    Remove emails from the database that are no longer present on the server.
    """
    async with db_pool.acquire() as conn:
        rows = await conn.fetch("SELECT id FROM emails")
        db_uids = {row["id"] for row in rows}
        server_uids_set = set(all_server_uids)
        uids_to_delete = db_uids - server_uids_set
        for uid in uids_to_delete:
            try:
                await conn.execute("DELETE FROM emails WHERE id = $1", uid)
                logger.info(f"Email {uid} deleted from DB (cleanup).")
            except Exception as e:
                logger.error(f"DB deletion error for email {uid}: {e}")

async def invoke_lambda(next_index):
    """
    Asynchronously re-invoke the AWS Lambda function for the next batch.
    """
    lambda_client = boto3.client("lambda")
    payload = {"start_index": next_index}
    try:
        response = lambda_client.invoke(
            FunctionName=LAMBDA_FUNCTION_NAME,
            InvocationType="Event",
            Payload=json.dumps(payload)
        )
        logger.info(f"Lambda re-invoked for batch starting at index {next_index}: {response}")
    except Exception as e:
        logger.error(f"Failed to invoke Lambda for next batch: {e}")

async def main_handler(event):
    """
    Main asynchronous handler:
      - Connects to IMAP to retrieve all UIDs.
      - Processes emails in batches using asynchronous techniques.
      - Cleans up deleted emails.
      - Re-invokes Lambda if additional batches remain.
    """
    start_index = int(event.get("start_index", 0))
    logger.info(f"Lambda invoked with start_index: {start_index}")

    # Initial connection to get all UIDs
    client = await connect_imap()
    uids = await fetch_uids(client)
    total_msgs = len(uids)
    logger.info(f"Total emails on server: {total_msgs}")
    await client.logout()

    # Set up asynchronous database connection pool
    db_pool = await asyncpg.create_pool(DB_URL)
    try:
        for i in range(start_index, total_msgs, BATCH_SIZE):
            uid_batch = uids[i:i+BATCH_SIZE]
            await process_batch(uid_batch, db_pool)
            # If there are more emails, re-invoke Lambda for the next batch
            if i + BATCH_SIZE < total_msgs:
                await invoke_lambda(i + BATCH_SIZE)
    finally:
        await cleanup_deleted_emails(uids, db_pool)
        await db_pool.close()

    return {"status": "completed", "processed": total_msgs, "total": total_msgs}

def lambda_handler(event, context):
    return asyncio.run(main_handler(event))

if __name__ == "__main__":
    # For local testing:
    test_event = {"start_index": 0}
    result = asyncio.run(main_handler(test_event))
    print(result)

import logging
import psycopg2
import time
from config import DB_URL

logger = logging.getLogger(__name__)
logging.basicConfig(level=logging.INFO)

def fetch_unprocessed_emails():
    """Fetches emails from PostgreSQL instead of IMAP."""
    conn = psycopg2.connect(DB_URL)
    cursor = conn.cursor()
    cursor.execute("SELECT id, subject FROM emails WHERE status = 'pending'")
    emails = cursor.fetchall()
    conn.close()
    return emails

def process_emails():
    """Processes emails using database instead of IMAP."""
    emails = fetch_unprocessed_emails()
    for email in emails:
        logger.info(f"Processing email: {email[1]}")
        # Placeholder for classification or flow logic
        mark_as_processed(email[0])

def mark_as_processed(email_id):
    """Marks email as processed in DB."""
    conn = psycopg2.connect(DB_URL)
    cursor = conn.cursor()
    cursor.execute("UPDATE emails SET status = 'processed' WHERE id = %s", (email_id,))
    conn.commit()
    conn.close()
    logger.info(f"Marked email {email_id} as processed.")

if __name__ == "__main__":

    while True:
        process_emails()

# Create a package directory inside the inboxflow-imap-sync folder
mkdir -p inboxflow-imap-sync/package

# Use the AWS SAM build image for Python 3.9 to install dependencies into the package directory
docker run --rm --platform linux/amd64 -v "$PWD":/var/task public.ecr.aws/sam/build-python3.9 \
  pip install --no-cache-dir --only-binary=:all: --target /var/task/inboxflow-imap-sync/package -r inboxflow-imap-sync/requirements.txt

# Copy your Lambda code into the package directory
cp -r inboxflow-imap-sync/*.py inboxflow-imap-sync/package/

# Change directory to the package folder and create the zip file
cd inboxflow-imap-sync/package
zip -r9 ../../${OUTPUT_ZIP} .
cd ../../

# Clean up the package directory
rm -rf inboxflow-imap-sync/package

echo "Lambda package created: $(pwd)/${OUTPUT_ZIP}"
